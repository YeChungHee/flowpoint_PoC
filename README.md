# 플로우포인트 테스트 페이지 (PoC)

276홀딩스 플로우포인트의 **내부 검증용 테스트 페이지**입니다.
업무 솔루션(발주·거래명세서·자금일보)으로 고객이 모이고, 쌓인 거래 데이터로 플로우스코어가 정교해지고, 그 점수로 플로우페이 심사 리스크가 줄어드는 선순환 구조를 화면에서 확인하는 데 씁니다.

> ⚠️ 모든 회사명, 금액, 수수료, 점수 산식은 **테스트용 가정값**입니다. 실제 신용평가나 심사 기준이 아니며, 실제 기업 정보나 개인정보는 넣지 않습니다.

## 여는 방법

`index.html` 파일 하나로 동작합니다. 설치할 것은 없습니다.

- 파일을 내려받아 브라우저(Chrome, Safari, Edge)로 열면 됩니다.
- 입력한 내용은 **그 브라우저에만** 저장됩니다. 다른 사람과 공유되지 않습니다.
- 화면 아래 **처음부터 다시 (시나리오 초기화)** 버튼을 누르면 가상 시나리오 처음 상태로 돌아갑니다.
- 상단 **⇄ 고객 화면** 버튼으로 고객 화면과 심사역 화면을 오갑니다.
- - 검증 순서와 회의용 질문은 [`docs` 폴더의 검증-시나리오](docs/)에 있습니다.

| 자금일보 | 매일 대표에게 보내는 형식의 자금 보고서와 오늘 챙길 일 |

| 매출업무 | 거래명세서 발행, 세금계산서 발행, 입금 확인, 독촉 알림, 플로우페이·유동화 신청 |
| 플로우스코어 | 매출처·매입처 점수(900점 만점), 기업평가 리포트, 상대 기업 동의 기반 정보 요청 |
| 정책자금·지원사업 | 예시 공고 목록, 관심 등록, 서류함 대조 |
| 서비스 진행 | 플로우페이(매입·매출 묶음)와 매출채권 유동화 신청·진행, 우리 회사 점수·이유·한도, 이의 제기, 마일리지, 기업 서류함 |
| 심사 (심사역 화면) | 심사 대기(점수 근거, 리스크 표시, 판단 사유), 집행 후 상환·연체 기록, 이의 제기 처리, 판단 기록(정답 데이터) |

## 개발 참고

- 한 파일 안에 화면(HTML), 디자인(CSS), 동작(JavaScript)이 모두 들어 있습니다. 외부 라이브러리는 쓰지 않습니다.
- 브라우저 저장 키는 `flowpoint-test-v6`이며, 저장 데이터 모양은 `seed()` 함수에서 확인할 수 있습니다.
  - `role`: 현재 역할. 고객(customer) 또는 심사역(reviewer)
  - `purchases`: 발주(매입) 목록. 발주일 `ordered`, 실제 지급일 `paidOn`. 상태는 결제 예정(ordered), 지급 완료(paid), 플로우페이 결제(financed), 플로우페이 상환 완료(repaid)
  - `sales`: 거래명세서(매출) 목록. 발행일 `issued`, 실제 입금일 `paidOn`, 세금계산서 `tax`·`taxOn`, 거래 상대 확인 `confirm`. 상태는 입금 대기(open), 입금 완료(paid), 유동화 완료(factored), 묶음 정산(bundled)
  - `apps`: 플로우페이·유동화 신청. 단계는 거래 상대 확인(confirm), 심사(review), 반려(rejected), 전자서명(sign), 채무자 통지(notice), 집행(done). 심사 판단 `decision`, 상환 결과 `outcome`(repaid, late)
  - `scoreLog`: 사건별 점수 변동 기록 / `disputes`: 이의 제기
  - `docs`, `consent`: 기업 서류함과 보관·재사용 동의
  - `mileage`, `log`, `reqs`, `fav`: 마일리지, 입출금 기록, 정보 요청 내역, 관심 지원사업
- 플로우스코어는 규칙 기반 산식입니다. 기본 점수(`BASE`)에 항목별 가감점을 더합니다. 거래처 점수는 `partnerFactors()`, 우리 회사 점수는 `myFactors()`에서 계산하고, 같은 함수에 과거 날짜를 넣어 월별 추이를 만듭니다. 한도는 `limitInfo()`입니다.
- 모든 동작 전후로 점수를 비교해 바뀐 점수만 `scoreLog`에 남깁니다(`logScores()`).

## 자동 점검

`tests/` 폴더의 스크립트로 브라우저 자동 점검을 돌릴 수 있습니다(Playwright 필요).

- `node tests/smoke.js <index.html 절대 경로>`: 모든 메뉴가 오류 없이 열리는지 확인
- `node tests/flow.js <index.html 절대 경로> [캡처 저장 폴더]`: 검증 시나리오 순서대로 한 바퀴를 돌며 점수 변동과 단계 전환을 확인하고, 안내서 캡처를 만듭니다
- 화면 전환은 주소 끝의 `#home`, `#orders` 같은 표시로 이루어집니다.
