# 플로우포인트 테스트 페이지 (PoC)

276홀딩스 플로우포인트의 **내부 검증용 테스트 페이지**입니다.
업무 솔루션(발주 파일 수집·발주·거래명세서·자금일보)으로 고객이 모이고, 쌓인 거래 데이터로 플로우스코어가 정교해지고, 그 점수로 플로우페이(구매 대행) 심사 리스크가 줄어드는 선순환 구조를 거래 문서·결제 알림까지 한 화면 흐름으로 확인하는 데 씁니다.

이번 판(v5)의 두 가지:
- **apple.com처럼 단순한 화면**: 고객사 대표가 처음 열어도 "돈이 괜찮은가, 오늘 뭘 해야 하나, 플로우페이 얼마 쓸 수 있나"가 바로 보이도록 화면에는 숫자·상태·버튼만 두고 설명은 ⓘ로 접었습니다. 색은 apple.com 값(바탕 #F5F5F7/#FFFFFF, 글자 #1D1D1F, 파란 버튼 #0071E3, 다크 #000/#1D1D1F·링크 #2997FF), 알약 버튼과 큰 둥근 카드, 화면마다 큰 한 문장 제목. 홈은 숫자 3개와 오늘 할 일 3개, 매입·매출 목록은 한 줄에 버튼 하나(나머지는 줄을 눌러 여는 상세 시트), 입력은 **+ 새 거래** 시트로 옮겼습니다.
- **매출 묶음 상환**: 플로우페이 상환은 신청 때 묶은 매출의 대금으로만 합니다. 묶은 매출 대금이 들어온 날 **오늘 276에 넘길 금액** 시트에서 **276에 넘기기**를 누르고, 납품액(마일리지 차감)을 모두 넘기면 자동으로 **상환 완료**(점수·감사 메일). 입금 예정일 + 7일(유예, 가정값)이 지나도록 넘기지 않으면 자동 **연체**, 연체 뒤에도 다 넘기면 **연체 후 완납**입니다.

> ⚠️ 모든 회사명, 금액, 가산율, 점수 산식은 **테스트용 가정값**입니다. 실제 신용평가나 심사 기준이 아니며, 실제 기업 정보나 개인정보는 넣지 않습니다.

## 여는 방법

`index.html` 파일 하나로 동작합니다. 설치할 것은 없습니다.

- 테스트 페이지 주소: https://yechunghee.github.io/flowpoint_PoC/ (예전 화면이 보이면 Cmd+Shift+R 또는 시크릿 창으로 여세요)
- 또는 파일을 내려받아 브라우저(Chrome, Safari, Edge)로 열면 됩니다.
- 입력한 내용은 **그 브라우저에만** 저장됩니다. 다른 사람과 공유되지 않습니다.
- 화면 맨 아래 **처음부터 다시 (시나리오 초기화)** 버튼(휴대폰은 하단 탭 **더보기** 안)을 누르면 가상 시나리오 처음 상태(테스트 날짜·역할 포함)로 돌아갑니다.
- 역할은 3가지입니다. **고객(대표)**(기본), **고객(담당자)**(사이드바 아래 **담당자로 보기**: 수집함 확인·수정만, 신청·최종 승인·전자서명은 "대표 승인 요청"), **심사역**(사이드바 맨 아래 역할 카드 **심사역으로 전환** / **고객(대표)으로 전환**). 휴대폰은 **더보기 → 역할 전환 / 담당자로 보기**입니다. 매입처는 역할이 아니라 `#link/…` 외부용 링크 화면으로 처리합니다.
- **날짜 이동(테스트)**: 맨 아래 막대(휴대폰은 더보기)의 **+1일 · +7일 · +30일** 버튼으로 테스트 날짜를 앞으로 옮겨 상환 매출 알림(D-30·D-7·당일·D+1), 넘김 지연 알림, D+7 뒤 자동 연체, 서명 재알림을 확인합니다. 현재 테스트 날짜가 옆에 보이고, **처음부터 다시**를 누르면 오늘로 돌아갑니다.
- 검증 순서와 회의용 질문은 [`docs` 폴더의 검증-시나리오](docs/)에 있습니다.

## 화면 구성

컴퓨터(가로 1024px 이상)에서는 왼쪽 사이드바, 태블릿(768~1023px)에서는 상단 가로 메뉴, 휴대폰(768px 미만)에서는 하단 탭 5개(홈·거래·스코어·서비스·더보기)로 이동합니다. 휴대폰의 거래 탭은 매입·매출 전환, 더보기는 수집함·거래 문서·결제 캘린더·자금일보·정책자금·지원사업·알림·날짜 이동·역할 전환·처음부터 다시를 담습니다. 화면 위 오른쪽 **알림** 버튼(안 읽은 건수)은 알림함입니다.

| 정보 → 정책자금·지원사업 | 더보기 | 예시 공고 목록, 관심 등록, 서류함 대조 |
| 심사 (심사역만, 맨 위) | 더보기 → 심사 | 고객사 포트폴리오, 이슈 피드(확인·조치 기록, 넘김 지연 포함), 심사 대기(AI 검토 보고서 예시, 상환 매출 비율, 리스크 표시, 판단 사유), 집행 후 관리(플로우페이는 자동 정산 결과 확인, 유동화는 상환·연체 기록), 이의 제기 처리, 판단 기록(정답 데이터) |
| (외부) 매입처 링크 `#link/…` | - | 매입처가 가입 없이 발주서 열람 → 전자서명 → 세금계산서(정발행 또는 역발행 승인) → 완료. 사이드바·탭 바 없음 |

신청은 4단계 시트로 나눠 진행합니다.

- 플로우페이(구매 대행형, 납품 전): ① 매입 확인 → ② 상환할 매출 묶기 → ③ 서류 확인 → ④ 납품액·상환 일정 확인 후 신청. 276이 매입처에서 사서 고객사에 납품액으로 판매합니다. 납품액 공급가액 = 매입 공급가액 × (1 + 가산율), 가산율은 결제 기간별 **30일 3.3% · 60일 6.6% · 90일 10%**, 부가세 10%. 결제 기간은 묶은 매출의 가장 늦은 입금일을 덮는 구간으로 제안됩니다. 화면은 세금계산서 형식(공급가액·세액·합계)이며 마지막 단계에 **최종 가격은 영업 담당과 협의 후 확정** 한 줄이 보입니다. 상환은 묶은 매출 대금으로만 합니다: 묶은 매출 합계(부가세 포함)가 넘길 금액(납품액 − 마일리지)보다 적으면 신청할 수 없고, 상환 일정은 입금 예정일 순서로 매출별 넘길 금액을 채웁니다(예: 한결푸드 4,400,000원 → 그린마켓 11,565,090원 = 15,965,090원). 매출처 계좌 변경 통지는 없고, 고객사가 입금일 당일 276에 넘깁니다. 다른 신청에 이미 묶인 매출은 고를 수 없습니다. ③에서 올려야 할 서류가 남아 있으면 버튼이 "서류 N건 남음"으로 막힙니다.
- 매출채권 유동화(납품 후): ① 양도 가능·계좌 변경 확인 → ② 채권 정보 → ③ 서류 확인 → ④ 확인하고 신청. 승인·전자서명 뒤 채무자 통지(승낙 확인)를 거쳐야 자금이 지급됩니다.
- 컴퓨터에서는 Enter로 다음 단계, Esc로 시트를 닫습니다.

글꼴은 맑은 고딕을 쓰고(웹폰트를 내려받지 않음), 맑은 고딕이 없는 맥·아이폰에서는 Apple SD Gothic Neo로 보입니다. 다크 모드는 기기 설정을 따릅니다.

## 개발 참고

- 한 파일 안에 화면(HTML), 디자인(CSS), 동작(JavaScript)이 모두 들어 있습니다. 외부 라이브러리는 엑셀 읽기용 SheetJS(`xlsx@0.18.5`, jsDelivr CDN) 하나뿐이며, 엑셀 파일을 올릴 때만 불러옵니다. 불러오지 못하면 오류 없이 CSV만 받습니다. 실제 외부 API(전자서명·알림톡·세금계산서·은행)는 쓰지 않고 화면 시뮬레이션으로 "연동 예정"을 표시합니다.
- 브라우저 저장 키는 `flowpoint-test-v6`이며, 저장 데이터 모양은 `seed()` 함수에서 확인할 수 있습니다.
  - `role`: 현재 역할. 고객 대표(ceo), 고객 담당자(staff), 심사역(reviewer). 예전 기록의 customer는 ceo로 바꿔 읽습니다
  - `dayOffset`: 날짜 이동(테스트) 일수. 모든 날짜 계산(`today0()`)에 더해집니다
  - `purchases`: 발주(매입) 목록. 발주일 `ordered`, 실제 지급일 `paidOn`. 상태는 결제 예정(ordered), 지급 완료(paid), 플로우페이 결제(financed), 플로우페이 상환 완료(repaid). 플로우페이 결제 건은 상환 금액 `repayAmount`·마지막 상환 매출 입금일 `repayDate`, 묶은 매출 `fundSales`, 묶음 상환 연체일 `repayLate`
  - `sales`: 거래명세서(매출) 목록. 발행일 `issued`, 실제 입금일 `paidOn`, 세금계산서 `tax`·`taxOn`, 거래 상대 확인 `confirm`. 상태는 입금 대기(open), 입금 완료(paid), 유동화 완료(factored), 묶음 정산(bundled)
  - `apps`: 플로우페이·유동화 신청. 단계는 거래 상대 확인(confirm), 심사(review), 반려(rejected), 전자서명(sign), 채무자 통지(notice), 집행(done). 심사 판단 `decision`, 상환 결과 `outcome`(repaid, late)와 연체 후 완납일 `lateRepaid`, 자동 정산 표시 `auto`. 플로우페이는 결제 기간 `tier`, 가산율 `rate`, 납품액 `saleSupply`·`saleVat`·`saleTotal`, 결제일 `payDate`, 마일리지 `mileage`, 넘길 금액 `repayTotal`, 유예일 `graceDays`(7), 상환 일정 `alloc`(매출별 `saleId`·`due`·`saleTotal`·`forward`), 넘긴 기록 `fwd`(건별 `saleId`·`amt`·`date`)
  - `scoreLog`: 사건별 점수 변동 기록 / `disputes`: 이의 제기
  - 새로 더한 칸(예전 기록은 `load()`에서 기본값으로 채움): `inbox`(수집 후보: 원본 파일·확인 필요 표시·상태 new/checked/approved/rejected), `consents`(수집 채널별 동의), `deals`(거래 문서 7종의 상태·보냄/열람/서명/완료 날짜, 입고 사진), `notifications`(상환 알림·넘김 지연·서명 재알림·감사 메일·심사 전달 기록), `issueLog`(심사역 이슈 확인·조치 기록), `lastApprovalPrompt`(역할별 승인 창 표시 날짜)
  - `docs`, `consent`: 기업 서류함과 보관·재사용 동의
  - `mileage`, `log`, `reqs`, `fav`: 마일리지, 입출금 기록, 정보 요청 내역, 관심 지원사업
- 플로우스코어는 규칙 기반 산식입니다. 기본 점수(`BASE`)에 항목별 가감점을 더합니다. 거래처 점수는 `partnerFactors()`, 우리 회사 점수는 `myFactors()`에서 계산하고, 같은 함수에 과거 날짜를 넣어 월별 추이를 만듭니다. 한도는 `limitInfo()`입니다.
- 모든 동작 전후로 점수를 비교해 바뀐 점수만 `scoreLog`에 남깁니다(`logScores()`).

## 자동 점검

`tests/` 폴더의 스크립트로 브라우저 자동 점검을 돌릴 수 있습니다(Playwright 필요).

- `node tests/smoke.js <index.html 절대 경로>`: 모든 메뉴(수집함·거래 문서·결제 캘린더·매입처 링크 포함)가 오류 없이 열리는지 확인
- `node tests/flow.js <index.html 절대 경로> [캡처 저장 폴더]`: 검증 시나리오 한 바퀴(수집함 승인 → 입금·세금계산서 → 플로우페이 신청(상환할 매출 묶기) → 거래 상대 확인 → 심사 승인 → 전자서명 → 매입처 링크 → 대금 지급·판매 세금계산서 → 납품 확인 → 묶은 매출 입금 확인 → 276에 넘기기 → 날짜 이동·상환 알림 → 완납·감사 메일 → 유동화 → 이의 제기 → 이슈 피드 조치 → 부록: 다음 날 넘김 지연 · D+8 자동 연체 · 늦은 납품 확인 후 연체 후 완납 → 초기화)를 돌며 금액·점수·상태를 점검하고(틀리면 종료 코드 1), 안내서 캡처 20장(1280×900, 2배 해상도)을 만듭니다. 예: `node tests/flow.js $PWD/index.html $PWD/docs/img`
- `node tests/inbox.js <index.html 절대 경로> [--shots=캡처 폴더] [--xlsx=xlsx.full.min.js 로컬 사본]`: 수집함 점검(CSV·엑셀 실제 읽기, AI 추출 예시, 담당자 확인 → 대표 승인, 승인 창, 엑셀 도구 불러오기 실패). `--xlsx`를 주면 CDN 대신 로컬 파일로 네트워크 없이 점검합니다. 실패가 있으면 종료 코드 1
